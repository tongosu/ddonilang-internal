## 배경

15줄기×6마루 구조는 2026-04-26에 확정됐다. 그 이후 사흘 넘게 완전히 다른 방향의 실질 작업이 쌓였다:

- 설정 헤더/누리마디 위상·경합/보개 표준팩(2026-07-06 지시문 1~10 계열)
- 7목적 고도화 G1(perf baseline, econ model-first, 적분기 pack, LLM 코퍼스, ko-common 승격, 진단 3층) — DAYRUN Tier A로 실제 구현
- 발표 전 동결 스윕(예약어/문법공간/오류코드 실측)
- SSOT 병합 준비/감사(지시문 12/13), 설계 정교화 ANNEX 6건(지시문 16)

이 작업들이 기존 15줄기 어딘가에 자연스럽게 속하는지, 아니면 로드맵이 놓치고 있는 새 줄기/마루가 있는지 한 번도 검토되지 않았다. 또한 07-06 재검증이 지적한 근본 결함 — **체커가 "닫힘 상태 문서 존재 여부"만 보고 "기능이 실제로 동작하는지"는 안 본다** — 는 구조 재검토와 함께 다뤄야 진짜 문제다.

### 2. 최근 산출물의 줄기 귀속 판정

아래 최근 산출물들이 기존 15줄기 중 어디에 속하는지, 아니면 어디에도 안 속하는지 표로 판정한다:

| 산출물 | 후보 귀속 줄기 | 판정 |
|---|---|---|
| 설정 헤더 정합/누리마디 위상·경합(지시문 1,3,4,9,10) | 가(언어코어)? | ? |
| 보개 표준팩(지시문 8) | 사(보개/게임)? | ? |
| 7목적 고도화 전체(econ model, 적분기, LLM 코퍼스, ko-common, perf baseline) | 다(수학)/파(경제사회)/거(AI개발보조)? 여러 줄기에 걸침? | ? |
| 발표 전 동결 스윕(예약어/문법공간/오류코드) | 가(언어코어)? 혹은 이 로드맵 밖의 별도 트랙? | ? |
| AI 닫힌 베타 프로토콜 | 거(AI개발보조)? 혹은 새 줄기? | ? |

각 산출물이 "기존 줄기에 억지로 끼워 맞춰지는지" 아니면 "정말 그 줄기 소속이 맞는지"를 판단 근거와 함께 적는다. 억지로 끼워 맞추지 말 것 — 안 맞으면 "귀속 없음"으로 남긴다.

### 3. 빠진 줄기/마루 후보

위 2번에서 "귀속 없음"으로 남은 산출물들을 근거로, 신규 줄기 후보가 필요한지 검토한다. 예시로 검토할 후보(채택 여부는 판단하지 말고 후보만 제시):
- "설정/거버넌스 심화" 줄기 — 설정 헤더, 누리마디 경합, SSOT 병합 프로세스처럼 언어 코어도 제품도 아닌 "프로젝트 운영 계약" 성격의 산출물들.
- "발표 전 동결" 마루(6번째 마루 추가, 또는 전 줄기 공통 가로줄) — 예약어/문법공간/오류코드/골든 커버리지처럼 줄기별이 아니라 전체 발표 준비에 걸친 것.

### 4. 검증 체계 결함 개선안

07-06 재검증이 지적한 "체커가 문서 존재만 본다"는 결함에 대해, 다음 두 방향의 개선안을 각각 장단점과 함께 제시한다(택일 아님, 둘 다 후보로):
- (A) 기존 체커를 실제 동작 검증(golden PASS, UI 배선 확인 등)으로 다시 짠다.
- (B) "닫힘" 등급 자체를 세분화한다(예: `문서만` / `백엔드만` / `배선완료` / `진짜닫힘`) — 지금 재검증에서 이미 쓰고 있는 `진짜닫힘`/`형식뿐`/`FAIL` 3단계를 정식 등급으로 로드맵 문서 자체에 못박는 안.

### 5. 우선순위 재조정 제안 (기존 GANADA_MATRIX_CORRECTED §재우선순위 제안을 갱신)
