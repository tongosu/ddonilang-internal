## 0. 목적

선행 제안서는 action 경합 파이프라인까지 정리했다. 이 문서는 결정성을 실제로 위협하는 남은 세 축 — **큰마디 전체 위상 순서**, **action 밖 상태 쓰기 경합**, **속마디 관측 격리** — 과 **reset 5종 상호작용**, **명명 충돌 정리**를 심화한다.

핵심 판단: "같은 입력 = 같은 세계"는 action merge만으로 보장되지 않는다. 한 큰마디 안에서 임자 본문·세움 재평가·훅·알림·덩이 적용이 **어떤 순서로 도는지**가 계약이 되어야 한다.

불변 전제 (변경 금지):

- 엔진 5계층 `tick_once()` 순서: **샘 → 이야기 → 누리 → 거울 → 보개**. 이 계약 위에 위상을 얹을 뿐, 순서 자체는 바꾸지 않는다.
- E-7C action 순서: `action_status 판정 → merge → 보람 계산 → obs/reward/terminated/truncated/info`.
- Sam ordering `(agent_id, recv_seq)`, Gate0 계약 물림(DR-178) snapshot/restore.
- `state_hash` 경계 (view/debug/diag/보개 제외).

## 1. 큰마디 위상표 v1 (초안)

한 큰마디의 canonical 위상. 엔진 계층에 대응시킨다.

| 위상 | 엔진 계층 | 내용 | 읽기 경계 | 쓰기 |
|---|---|---|---|---|
| P0 마디 열기 | 샘 | `now_madi` 확정 (마디 번호는 열기 시점에 증가) | - | 마디 카운터만 |
| P1 입력 봉인 | 샘 | raw 입력 수집·봉인: 사람/UI/일정/재연 + 슬기 패킷 중 `target_madi` 도달분. completion 게이트(`#모두필요/#빈칸채움`) 판정. view-only 입력 분리 | 직전 커밋 상태 | `InputSnapshot`만 |
| P2 행동 전처리 | 이야기(전처리) | 바른꼴화 → 검증/보정(`맞음/가만히/잘림/거부`; `가늠/갈래` 참조는 직전 커밋 상태 read-only) → 거르기 → 합치기(merged_action) | 직전 커밋 상태 | 없음(중간 산출물만) |
| P3 세계 갱신 | 이야기(본체) | 아래 3a~3g. world read-only, **patch 생성만** | 직전 커밋 상태 + 자기 tentative | patch/미루기 |
| P4 커밋 | 누리 | 덩이 순차 커밋 → 미루기 일괄 적용 → patch 적용 → `state_hash` 계산 | - | world |
| P5 보람/판끝 | 이야기/누리 경계 | 적용 후 상태 기준 보람·판끝·잘림 판정 (E-7C 순서 준수) | 커밋 후 상태 | reward/done 기록값 |
| P6 기록 | 거울 | step_record: raw/normalized/status/merged/applied + reward/done + hashes | - | 기록층 |
| P7 방출 | 보개 | `뒤살핌` 정책에 따른 관찰 방출, view trace | 커밋 후 상태 | view_meta만 |

### 1.1 P3 세계 갱신 내부 순서

| 하위 | 내용 | 비고 |
|---|---|---|
| 3a | `(시작)할때` | 첫 마디/episode 시작에만 |
| 3b | merged_action 의미 반영 + `(매마디)마다` 본문 실행 | 임자 실행 순서 = **결정적 열거 필수** (아래 OQ-1) |
| 3c | 세움 재평가 / 흐름씨 전파 | 명령적 갱신 후 관계 재확립. 1회 평가, 순환 의존은 오류 (OQ-2) |
| 3d | `바뀔때마다` | 상태머신 전이 직후, 3b/3c 중 발화 |
| 3e | `될때 / 인 동안` 판정 | 커밋 후보 상태에서 **1회 판정**. 본문 효과는 같은 마디 patch에 포함하되 **재트리거 금지(1-pass)** (옵션 B: 다음 마디 이월; 권고 A=1-pass) |
| 3f | 계약(물림) post 검사 | Gate0 snapshot/restore 계약 그대로 |
| 3g | 훅/임자가 발신한 알림(`~~>`) | **이번 마디에 처리하지 않고 다음 마디 P1 입력 큐로** 넘긴다 (cascade 차단, 샘 경유 일원화) |

### 1.2 위상 불변식

- 위상은 DAG다. 건너뜀은 있어도 **재진입 없음** (같은 마디에서 P3 → P2로 돌아가지 않는다).
- 위상 내 모든 컬렉션 순회는 결정적 열거(선언 순서 또는 사전순)를 명시한다.
- 봉인 대상은 **raw 입력**이다. merge 결과는 P2에서 결정적으로 재계산 가능해야 하며 기록(P6)에는 raw와 merged를 모두 남긴다 (감사: raw 보존, 재현: 재계산 검증).

### 1.3 열린 질문 (OQ)

- **OQ-1** 임자 실행 순서 정본: (가) 파일 선언 순서 (나) `agent_id` 사전순. 권고: **(가) 선언 순서** — "파일이 진리, 모양이 기능" 원칙 정합.
- **OQ-2** 세움 ↔ 매마디 상호 갱신: fixpoint 반복 없이 1회 평가로 제한하고, 순환 의존은 정적/실행 오류로 볼지.
- **OQ-3** P2(전처리)를 샘 소속으로 볼지 이야기 소속으로 볼지 — 어느 쪽이든 raw 봉인 + 결정적 재계산 불변식은 동일.
- **OQ-4** 훅 4가족 중 `마다`의 변형(`(N마디)마다`)이 P3 어느 시점에 판정되는지.

## 2. 상태 쓰기 경합 × `덩이 {}` / `미루기`

action merge가 다루지 못하는 경합: **같은 마디에서 둘 이상의 임자/규칙이 같은 상태를 쓰는 경우**.

### 2.1 경합 분류

| 분류 | 상황 |
|---|---|
| W1 | 같은 마디, 두 patch가 같은 키에 즉시 대입 |
| W2 | 복수 `미루기`가 같은 대상을 겨눔 (덩이 끝 적용 시 충돌) |
| W3 | merged_action의 의미 반영과 규칙 쓰기가 같은 키에 충돌 |

### 2.2 해소 옵션

| 옵션 | 내용 | 장점 | 위험 |
|---|---|---|---|
| (가) FATAL | `E_MADI_WRITE_CONFLICT` 결정적 오류 | 침묵 마스킹 없음, 교육 진단 가치, replay 안정 | 대규모 시뮬에서 불편 |
| (나) 결정적 last-writer | 임자 실행 순서(OQ-1) 기준 마지막 쓰기 승리 | 편의 | 조용한 덮어쓰기 — 버그 은폐 |
| (다) 병합 연산 한정 | 교환·결합 연산(`보탬` 계열: 더하기 등)만 다중 쓰기 허용 | 수학적 안전 | 표면 설계 필요 |

**권고: v1 기본 = (가) FATAL, (다)를 명시적 opt-in으로.** (나)는 채택하지 않는다. 이유: pre-release zero legacy 단계에서 가장 엄격한 기본을 잡는 것이 결정성 철학과 교육 목적 모두에 맞고, 완화는 나중에 열 수 있지만 조이는 것은 어렵다.

### 2.3 `덩이`와 커밋 계층

- `덩이 {}` = 마디 내 **부분 원자 단위**. `미루기` 적용 시점 = 해당 덩이 끝.
- 덩이 간 순서 = 프로그램 순서 (결정적).
- 마디 끝 P4 = 최종 커밋. 덩이 커밋은 P4 이전의 중간 단계이며 `state_hash`는 P4에서만 확정.
- 계약(물림) 복원은 덩이 경계가 아니라 **계약 구역 진입 시점** 기준 (Gate0 계약 유지).

## 3. 속마디 관측 격리 불변식

1. 속마디에서의 읽기 = **직전 큰마디 커밋 상태 + 자기 자신의 local tentative만**.
2. 다른 임자의 tentative/proposal은 비가시 (snapshot isolation).
3. 따라서 **속마디의 수·순서는 커밋 결과에 영향을 주지 않는다** (view trace 제외). 이것을 pack으로 검증 가능한 불변식으로 둔다.

협동 preview(다른 임자의 예상 행동을 보여주기)가 필요하면 **명시적 view-only 채널**(보개층)로만 제공하고, 세계 읽기 경계에는 넣지 않는다.

## 4. reset 5종 상호작용표 v1

`판다시/마당다시`는 lifecycle unit(`판{}/마당{}`)이 designed 단계이므로 질문 칸으로만 채운다.

| 항목 | 보개다시 | 누리다시 | 판다시* | 마당다시* | 모두다시 |
|---|---|---|---|---|---|
| world state | 유지 | 초기화 | Q | Q | 초기화 |
| `설정 {}` 재읽기 | 안 함 | Q (아래 OQ-R1) | Q | Q | 전체 재읽기 |
| `설정.누리` 시앗 재적용 | 안 함 | **권고: 재적용** (same-seed restart 재현 목적) | Q | Q | 재적용 (새 episode) |
| 샘 미적용 입력 | 유지 | 권고: 폐기 | Q | Q | 폐기 (확정 준함) |
| 슬기 pending 패킷 (`target_madi` 미래분) | 유지 | 권고: 폐기 | Q | Q | 폐기 |
| live control / view override | 유지 | Q | Q | Q | 비보존 (v23.0.7 확정) |
| 거울 기록 | 연속 | 연속 + 경계 마커 | Q | Q | 새 episode 기록 |
| 보개 view 상태 | 초기화 | 정책 따름 | Q | Q | 초기화 |
| `state_hash` | **불변 (확정)** | 초기화 경로 재실행 | Q | Q | 새 episode |

- **OQ-R1**: `누리다시`가 `설정.누리`만 재읽는지, `설정.실행`까지 재읽는지. 권고: 누리 절만 — 실행 정책 변경은 `모두다시` 요구.
- 이 표는 지시문 9-1 "결과영향 키 분류"와 교차 참조한다: reset 시 재적용되는 키 = 결과영향 키의 부분집합.

## 5. 명명·키 충돌 정리

1. **`합치기갈래` 신설 반대 — `행동모음갈래` 값 확장 권고.** 차림새 표의 `행동모음갈래`(차례모음/보탬모음)가 이미 수집·합침 축이다. merge policy를 별도 키로 만들면 두 키가 같은 의미 공간을 나눠 갖는다. 확장 후보: `차례모음`(turn_order 성격) / `보탬모음`(가산 병합) / `앞선모음`(priority) / `다수결모음`(majority) / `자리모음`(slot_owner).
2. **`rollback` 표면 금지 — 정본은 `되물림`.** D-001이 generic rollback = `되물림`으로 이미 잠갔다. 고급 옵션 표기도 `되물림`을 쓴다.
3. **순우리말 후보 병기**: `accepted_madi` → `받은마디`, `target_madi` → `닿을마디`, `seulgi_latency_madi` → `지연마디`(기존), `world_family` → `공간갈래`(기존 후보와 통일), `initial_state_ref` → `첫상태참조`.
4. **`세계영향경계: InputSnapshot.` 키 제거 권고.** 설정은 자유도가 있는 것만 담는다. 불변식의 재진술은 문서 설명층으로.
5. **`늦은제안다룸` 값 후보**: `버림 / 이월 / 다시매김(재검증)`. 권고: v1은 `버림`만 (이월·재검증은 replay 의미 복잡화 — 후속).

## 6. 선행 제안서 §8 (기본값/고급 노출)에 대한 검토 의견

- 방향 승인. "동기식 큰마디 commit 기반 결정적 turn/tick engine"이라는 기본형 규정과 §8.6 판단 기준 6문항은 좋다.
- 주의 1: 고급 preset 3종(`물리실험고급/슬기실험고급/경합실험고급`)은 **차림새 정본 집합(5종 확정)의 enum 확장**이므로 SSOT 변경 사항이다. proposal 표기임을 유지하고 차림새 closure와 함께만 승격.
- 주의 2: §8.4의 `rollback` 후보는 위 5-2에 따라 `되물림`으로 표기 통일.
- 주의 3: `공정성갈래`는 결정성과 충돌 가능성이 표에 이미 적혀 있으므로 long-term 연구 후보 유지가 맞다.
