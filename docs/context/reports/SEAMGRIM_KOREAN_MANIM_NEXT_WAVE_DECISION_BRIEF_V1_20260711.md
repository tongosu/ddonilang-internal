## 1. 판정 요약

Wave 1은 셈그림 UI V2의 제품 셸, 진자 `view_plan.v1` 후보, 고정·맞춤·따름 카메라, 각도재기, 봉인 관측 trace와 오프라인 반응 평가까지 실제 제품 경로에 놓았다. 다음 작업은 한국어 Manim의 표현 폭을 넓히기 전에 셈그림의 한 사용자 흐름을 닫아야 한다.

다음 수직 흐름을 하나의 장기 개발 단위로 채택한다.

```text
배우기에서 실행
-> 실험실에서 조절값 변경
-> 새 InputSnapshot/실행 계보
-> committed observation에 라이브 반응
-> 그래프·공간 장면·관찰값·DDN 뜻 연결
-> 만들기에서 활동 순서 구성
-> 같은 수업을 다시 실행하고 검증
```

이 웨이브의 목적은 영상 내보내기나 새 문법이 아니다. 낯선 사용자가 하나의 물리 수업을 보고, 바꾸고, 이유를 확인하고, 수업 순서를 만들 수 있는 제품 흐름을 닫는 것이다.

## 3. 이번에 확정해도 되는 구현 계약

다음은 기존 결정과 제품 증거에서 직접 이어지므로 다음 개발 목표의 고정 입력으로 사용한다.

1. 보기 반응은 committed observation을 읽는 순수 투영이며 세계를 쓰지 않는다.
2. 라이브 반응은 세계 hook runtime을 사용하지 않는다.
3. 라이브와 오프라인 경로는 predicate core와 테스트 벡터를 공유한다.
4. 동일한 봉인 trace를 온라인 평가기에 순서대로 넣으면 오프라인 schedule과 같은 발화 마디·동작열이 나와야 한다.
5. 같은 계보·마디의 같은 payload 재전달은 멱등이다. 다른 payload 재전달과 역순 전달은 진단한다.
6. 조절값 변경은 기존 InputSnapshot 경로로 새 실행 계보를 만든다. 보기 반응은 새 계보에서 초기화된다.
7. `state_hash`에는 세계 상태만 들어간다. view plan, 반응 결과, 카메라, 수업계획은 참여하지 않는다.
8. 의미 연결은 명시적 anchor/ref로만 한다. 변수명·문자열 추측은 금지한다.
9. 수업 활동 전환은 V0 도구층 runner가 소유한다. 정본 `마당{}` runtime을 선행 조건으로 만들지 않는다.
10. 수업계획은 새 DDN 문법으로 시작하지 않는다. V0는 도구층 TOML과 정규화된 내부 AST로 제한한다.

## 4. UI 잔여 문제 판정

4공간 셸은 생겼지만 기존 기능이 여전히 같은 화면에 남아 있다. 이는 구현 완료가 아니라 이행 단계다.

- 배우기 탐색 줄에 교과 분류, 배포 열기, 붙여넣기, 묶음 복사·저장, 교과 만들기가 동등한 버튼으로 남아 있다.
- 실행 화면에 숨은 학생/교사 스위치와 교사용 배포 동작이 남아 있다.
- 설명 진입점이 상단 버튼과 하단 정보 영역으로 중복될 수 있다.
- 만들기의 DDN 편집은 수업 구성과 연결되지 않는다.
- 현재 수업은 단일 실행 화면이지 활동 순서를 따라가는 수업 runner가 아니다.

다음 원칙으로 정리한다.

| 공간 | 한 가지 주 작업 | 포함 | 제외 |
|---|---|---|---|
| 배우기 | 수업을 골라 따라가기 | 대표/샘플/검색, 활동 진행 | 저작·배포 설정 |
| 실험실 | 값을 바꾸고 비교하기 | 허용 조절값, 실행 계보, diff | 역할 선택 |
| 만들기 | 세계와 수업을 만들기 | DDN, 수업 구성, 미리보기 | 학생 모드 |
| 배포 | 잠금과 전달 준비 | 꾸러미, 제출/회수 설정 | 세계 편집 |

역할은 실행 중 토글이 아니라 배포 구성이다. 이번 웨이브는 배포 profile 자체를 완성하지 않지만, 학생/교사 런타임 토글을 새 기능의 전제로 삼지 않는다.

## 5. 수업계획 V0 판정

수업계획은 다음 최소 소유권만 가진다.

- 활동 순서와 제목
- 활동 종류: `observe | change | compare | explain`
- `preset_ref`
- `allowed_controls`
- `question`
- `check_ref`
- `view_plan_ref`

수업계획은 세계 계산, 카메라 좌표, 렌더링 primitive, 정답 공개 정책을 소유하지 않는다. 공통 필드는 lesson meta를 복제하지 않고 ref로 연결한다.

V0 저작 원본은 `lesson_plan.v0.toml`, 제품 내부 정규형은 `lesson_plan.v0` AST로 한다. 목록 편집과 계획 코드 편집은 같은 AST를 사용하고 왕복 무손실 golden을 가져야 한다. `수업{}` 표면은 이번 범위 밖이다.

## 7. 개발 배치 판정

설계·판정은 이 문서에서 닫고, 제품 구현은 VS Code Codex의 장기 목표로 넘긴다. 이 선택은 능력 차이가 아니라 작업 형태 때문이다. 현재 Codex 앱은 SSOT·제안·구현을 교차 판정하는 데 쓰고, VS Code Codex는 고정된 계약 아래 제품 코드·브라우저·pack을 오래 실행하는 편이 효율적이다.

구현 중 계약 변경이 필요하면 임의 확장하지 않고 질문 큐에 남긴다. 단순 구현 세부는 Codex가 자율 결정한다.

## 8. 닫힘 주장

이 판정서는 `닫힘-문서`조차 제품 기능에 대해 주장하지 않는다. 다음 목표의 각 관문은 실제 제품 행동과 browser/runner 증거가 있을 때만 `닫힘-동작`으로 표시한다.
