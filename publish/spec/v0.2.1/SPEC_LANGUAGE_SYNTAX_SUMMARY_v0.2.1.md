## 적용 타입과 씨자리

```ddn
(셈수)차림
(글, 셈수)짝맞춤
(된씨)맺음
((셈수)차림)차림
```

사용자 코드의 씨자리 선언은 `가씨:씨자리`처럼 한글 이름만 정본이다. `T/U/V`와 `List<T>` 같은 표기는 영어
언어와 비교해 설명할 때만 쓰는 meta 표기이며 또니랑 입력 별칭이 아니다. 공백은
타입 적용 판별 기준이 아니고 문맥이 판별한다. formatter는 적용 타입을 붙여 출력한다.

```ddn
(왼씨:씨자리, 오른씨:씨자리)짝:이름씨 = {
  왼:왼씨.
  오른:오른씨.
}.
```

`(된씨)맺음`은 성공 타입 하나만 받는다. 성공은 `#잘됨`, 실패는 `#안됨`이고 실패
payload는 `이유:글`이다.

## 함수 타입

```ddn
가씨 --> 나씨
(가씨, 나씨) --> 다씨
(가씨 --> 나씨) --> 다씨
```

`-->`는 타입 위치에서만 사용하는 비결합 화살표다. 고차 함수 타입은 괄호로 결합을
명시한다. `T -> U`를 함수 타입 입력 별칭으로 만들지 않는다. `식 -> 자리.`는 오른쪽
대입 입력으로 유지하며 정본 출력은 `자리 <- 식.`이다. 이 문법 결정은 함수값의
저장·반환·capture·효과·직렬화 제품 지원 완료를 뜻하지 않는다.

## 구실 정의와 구현

```ddn
그려질수있음:구실 = {
  (맡은이:맡은씨~을~를, 판:그림판~에)
  그림명령만들:그림명령:셈씨~를
  보기만~으로 갖추어야함.
}.

(맡은이:공~을~를, 판:그림판~에)
표준원그리기.그림명령만들:그림명령:셈씨 = {
  ...
}.

공~은 표준원그리기~로
  그려질수있음~이라는 구실~을 맡음.
```

`맡은씨`는 구실 안의 정적 자기 타입이고 `맡은이`는 모든 요구·구현의 첫 receiver다.
`갖추어야함`은 요구, `맡음`은 구체 대상의 채택을 뜻한다.

## generic의 구실 요구

```ddn
(
  그릴씨:씨자리,
  그릴씨~는 그려질수있음~이라는 구실~을 맡아야함,
  맡은이:그릴씨~을~를,
  판:그림판~에
) 그리기:그림명령:셈씨 = {
  ...
}.
```

머리 순서는 씨자리 선언, 구실 요구, 일반 입력 핀이다. 타입은 필수 입력 핀에서만
1계 명목·불변 방식으로 추론한다. 반환 타입만으로 정해야 하는 output-only generic과
호출부 명시 타입 인자는 v0.2.1 V1 표면에 없다.

## 호출

```ddn
(공값~을, 판~에) 그림명령만들기.

(공값~을, 판~에)
그려질수있음.그림명령만들기.
```

인자가 앞에 온다. 둘 이상의 구실이 같은 요구 이름을 제공해 모호할 때만
`구실이름.요구함수기`로 한정한다. 후위 method 호출은 정본이 아니다.
